# P16.6 首页响应式布局最终修复与 UI 2.0 冻结报告 (P16_6_UI_FINAL_REPORT.md)

> 分支：`feature/compose-modernization`
> 目标：彻底解决实机首页中文字换行不自然、转储与密钥编辑标题被省略号截断、双列空间狭窄导致的排版失衡问题，正式冻结 KernelSU 风格 UI 2.0。

---

## 一、布局问题根因与前后架构对照

### 1.1 根因剖析
在此前的 UI 2.0 探索中，首页双列卡片（Read/Write、Dump/Keys）均强制采用“左侧图标 + 右侧标题/说明”的横向排布。
在常见 360dp–393dp 手机屏幕上，双列卡片单张宽度仅约 165dp–180dp，扣除图标（36dp）及内外边距后，右侧文字可用宽度不足 100dp：
- 导致“编辑 / 分析转储文件”与“编辑 / 新建密钥文件”等长标题因宽度不足触发 `TextOverflow.Ellipsis` 被生硬截断显示为“编辑 / 分析转储…”；
- 导致“读标签”与“写标签”下方的说明文字被挤压成每行仅 3–4 个字，发生多行不自然换行；
- 卡片内部出现大量无意义空白与横向空间浪费。

### 1.2 重新组织后的架构对照

| 区域 | 优化前结构 | P16.6 优化后最终结构 | 解决的痛点 |
| :--- | :--- | :--- | :--- |
| **NFC 状态区域** | `MctStatusCard` (Padding 12dp) | `MctStatusCard` 紧凑 Hero 卡片 | 保持实时状态监听与设置跳转，高度协调 |
| **核心读写区域** | 2 列横向流（图标在左，文字在右，文字宽度狭窄） | **2 列纵向居中流 (`CoreActionCard`)**：<br>- 顶部 40dp 矢量图标徽章；<br>- 中间 15sp Bold 标题；<br>- 底部精简说明（读：`认证并读取转储`；写：`写入、克隆或格式化`）；<br>- 居中对齐，高度统一 104dp。 | 文字横向拥有全卡 ~140dp 充足空间，**单行优雅呈现，彻底消除不自然折行** |
| **文件管理区域** | 2 列狭窄横向卡片（标题被截断为省略号） | **单列分组列表 (`MctSettingGroup`)**：<br>- 项 1：`编辑 / 分析转储文件`<br>- 项 2：`编辑 / 新建密钥文件`<br>- 左侧 34dp 矢量图 → 中间完整标题 → 右侧导航箭头 `›`。 | 占满全宽（~330dp 可用宽度），**标题完整显示，彻底消除省略号截断** |
| **工具与帮助** | 2 列分散卡片 | **2 列紧凑卡片 (`SecondaryActionCard`)**：<br>- 统一 58dp 高度；<br>- 统一 32dp 矢量图标与 13.5sp 标题；<br>- 间距 10dp。 | 视觉比例均衡，触控区域充沛 |

## 二、响应式规则与极值测试覆盖

1. **窄屏设备 (320dp ~ 360dp)**：
   - 核心读写卡片说明文字设置 `maxLines = 2, overflow = TextOverflow.Ellipsis`，即使在 320dp 极窄屏或系统字体放大至 1.3x 时，依然自适应换行完整展示，绝不截断；
   - 文件管理单列卡片独占横向宽度，彻底规避双列拥挤问题。
2. **大字体缩放场景 (1.3x ~ 1.5x)**：
   - 卡片高度统一采用 `defaultMinSize(minHeight = ...)` 自适应最小高度约束，随字体无级伸展，不会出现按钮被挤出屏幕或内容重叠。
3. **系统 Insets 与触控目标**：
   - 全页面保持 `Scaffold(innerPadding)`，避让状态栏与手势导航条；
   - 所有卡片与列表项触控有效区域均远超 48dp 无障碍标准。

## 四、UI 2.0 状态冻结声明

经过 P16.0 至 P16.6 的多轮迭代，MCT 的现代技术工具视觉体系（KernelSU 风格 UI 2.0）已在以下维度完全成熟并达到稳定状态：
1. **配色与暗色层次**：深灰底色 `#0D1117` + 浮层容器 `#161B22` + 1dp 轮廓描边 `#30363D`，彻底告别平铺灰；
